# 需求批量拆分清单
输出一个 JSON 数组（严格 JSON，不要输出任何解释文字或代码块围栏）。

每条需求的字段：
- `title`：需求标题，动宾结构，能单独看懂（必填，不超过 60 字）
- `description`：需求描述，写清角色、场景、业务规则与输入输出（可分段）
- `acceptance`：验收要点，用「1. 2. 3.」列可验证的结果
- `modulePath`：建议归属的功能点路径，优先从「项目功能点参考」里原样选取（如 `交易/支付`）；没有把握就留空
- `priority`：P0 / P1 / P2 / P3，按业务影响与阻塞关系判断

拆分规则：
1. 按**可独立验收的业务能力**拆，一条需求只讲一件事；不要把「登录 + 下单 + 退款」塞进同一条
2. 原文里明确属于同一流程前后依赖的部分可以合并；跨模块的必须拆开
3. 原文缺失但必须澄清的信息，写进该条 `acceptance` 的「待确认」项，不要自行编造业务规则
4. 条数不超过「期望条数上限」；上限没给时按原文信息量决定，通常 3~10 条
5. 标题不要带「需求一」「第一部分」这类序号前缀，编号由系统生成
