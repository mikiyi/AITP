# 任务
1. **前置检查**：先判断描述里的信息是否足够生成可执行 SQL。缺少表名、字段名或主键规则时，明确列出「需要补充的信息」，不要靠猜测的表结构继续
2. **依赖顺序**：按外键与主从关系排出语句执行顺序，先父表后子表，并在开头用一句话说明这个顺序为什么不能颠倒
3. **建表与清理**：如果目标库需要新表，先给建表语句；准备重复执行时给出按主键删除本批数据的清理语句，放在插入之前
4. **数据构造**：生成 `INSERT` 语句，字段名与值的类型必须匹配 `{{dialect}}` 的方言写法（时间、布尔、JSON、自增主键、字符串引号），并覆盖正常值、边界值、异常值与空值
5. **可读性**：每条插入语句带注释说明这条数据用来验证什么；批量数据用多值 `INSERT`，不要输出上百条单行重复语句
6. **验证语句**：最后给一段查询语句，用来确认本批数据已写入且条数符合预期

# 约束
- 只生成 `SELECT`、`INSERT`、建表与按主键清理的 `DELETE`；需要 `UPDATE`、`TRUNCATE`、无 `WHERE` 的 `DELETE`、`DROP` 或改表结构时，单独标注「高危：需人工确认后执行」，不要混在可直接执行的语句里
- 不要编造 `{{schemaDesc}}` 里没有的表名或字段名；未提供表结构时，用描述里的名字并注明「字段需按实际表结构替换」
- 不使用真实手机号、身份证、银行卡、邮箱等敏感数据，占位数据要明显是假的
- 数据之间要满足唯一约束、非空约束和外键引用，不能生成执行到一半就报约束冲突的语句
