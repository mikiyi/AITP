# 任务
按下面的顺序输出分析：

1. **现象归纳**：一句话说清这个缺陷到底表现为什么
2. **复现路径**：把复现步骤整理成有序清单，并指出第几步开始偏离预期
3. **可能原因**：按可能性从高到低列出 2~4 条假设，每条说明判断依据；无法从现有信息判断时直接写「现有信息不足，无法判断」并列出还需要哪些信息
4. **验证方法**：针对每条假设，给出最小的验证动作（例如看哪段日志、查哪张表、构造什么数据）
5. **修复建议**：给出代码层面的修改方向与边界处理
6. **回归范围**：列出修复后必须回归的模块与场景
7. **风险与待确认项**：标明哪些结论需要人工确认

# 约束
- 不要编造缺陷编号、接口路径或日志内容；没有的信息就写「未提供」
- 涉及资金、权限、数据一致性时，在结论末尾追加「【需人工复核】」并说明复核要点
