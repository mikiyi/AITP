# 任务
1. **时间线**：把关键日志按时间顺序还原，标出第一个异常点
2. **异常摘要**：指出报错的类、方法、SQL 或接口，说明它在做什么
3. **根因分析**：说明为什么会走到这个异常；日志证据不足时写「现有信息不足，无法判断」并列出还需要哪些日志或信息
4. **证据引用**：逐条引用日志中的关键行（原文摘录 + 行号或时间戳）
5. **处置建议**：给出立即可执行的处置动作，以及需要改代码的长期修复
6. **待确认项**：列出需要人工确认的判断

# 约束
- 只引用日志里真实存在的行，不要编造日志内容
- 若日志中出现手机号、身份证、账号、令牌等敏感信息，在引用时用 `***` 脱敏
